## 11. 函数设计规范

> **速览**: 函数简短单一职责；局部变量≤5-10个；≤3行的函数才内联；优先用内联函数而非宏

### 11.1 函数长度和复杂度

**Linux 内核标准**：

- 函数应该简短而漂亮，只做一件事情
- 函数应该可以一屏或两屏显示完（80x24 终端）
- **最大长度与复杂度和缩进级数成反比**

**本地变量数量**：
- 不应超过 **5-10 个**
- 超过则应该拆分成更小的函数
- 人脑一般能同时跟踪 7 个不同事物

**简单 case 语句的例外**：
如果函数理论上很简单，只是有一个很长的 case 语句，即使很长也可以接受。

### 11.2 内联函数的使用

**Linux 内核警告：过度使用 inline 会使内核变大，反而降低性能**。

**基本原则**：
- **超过 3 行的函数不要内联**
- 例外：参数是编译时常量，编译器能优化掉大部分代码

**不要给 static 且只用一次的函数加 inline**：
- gcc 会自动内联
- 移除 inline 的争论得不偿失

**优先使用内联函数而非宏**：
```c
// ✅ 推荐：内联函数
static inline int max_val(int a, int b)
{
        return a > b ? a : b;
}

// ❌ 避免：宏（除非必要）
#define MAX_VAL(a, b) ((a) > (b) ? (a) : (b))
```
